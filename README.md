# PrefixSelection

Ансамблирование языковых моделей с **несовместимыми токенизаторами** через посимвольную (character-level) агрегацию распределений.

Репозиторий содержит референсную реализацию метода Prefix Selection и CLI для интерактивных запусков.

---

## 1. Задача

Классическое ансамблирование LLM усредняет распределения вероятностей над словарём:

```
p_ens(t) = (1/N) · Σ p_i(t)
```

Это корректно только если у всех моделей общий словарь. Для произвольных моделей с Hugging Face это не так:

| Модель | Токенизатор         | Размер словаря | Разбиение `"Paris"` |
| ------ | ------------------- | -------------- | ------------------- |
| Qwen   | BPE (tiktoken-like) | ~152 000       | `Paris`             |
| Llama  | SentencePiece BPE   | ~128 000       | `Par` + `is`        |
| Gemma  | SentencePiece       | ~256 000       | `P` + `aris`        |

Токен `id=1234` в одной модели и в другой — разные строки. Суммировать такие распределения нельзя.

## 2. Принцип работы

Prefix Selection переносит агрегацию с уровня токенов на **уровень символов** — единственное общее пространство для всех токенизаторов.

Ансамбль выбирает не токен, а строковый префикс: символ за символом, пока распределения всех моделей не схлопнутся до одного кандидата. Полученная строка дописывается к ответу, и шаг повторяется.

## 3. Алгоритм

Обозначения: `N` — число моделей, `K` — `top_k` (по умолчанию 5), `s` — сгенерированный текст.

**Шаг генерации** (`PrefixDense.runpipe`):

1. Каждая модель `i` получает свой чат-шаблон (`apply_chat_template`) + `s` и возвращает top-K распределение по строкам токенов: `D_i = {token_str: prob}`.
2. Проверка EOS (`_check_eos`): если ≥ 50 % моделей ставят стоп-токен на первое место **или** средняя масса стоп-токенов ≥ 0.5 — генерация завершается.
3. Посимвольный консенсус (`match_chars`) — см. ниже.
4. Возвращённая строка дописывается к `s`, переход к п. 1. Лимит — 300 шагов.

**Посимвольный консенсус** (позиция `c = 0, 1, 2, …`, лимит 128 символов):

1. Для каждой модели считается распределение по символам в позиции `c`:
   `P_i(ch) = Σ { p(t) : t[c] == ch }`.
2. Если токен `t` короче позиции `c` (`len(t) ≤ c`), он **достраивается**: делается дополнительный forward pass модели `i` на `s + t`, и токен раскрывается в `t + t'` с вероятностью `p(t)·p(t')` (`find_the_suitest_token`). Это выравнивает токенизаторы по длине.
3. Символы усредняются по ансамблю: `P(ch) = (1/N) · Σ P_i(ch)`. Побеждает `argmax`.
4. Победивший символ дописывается к префиксу; распределения фильтруются — остаются только токены, начинающиеся с текущего префикса.
5. Как только у **каждой** модели в отфильтрованном распределении остался ровно один кандидат — возвращается их общий префикс (`os.path.commonprefix`).

### Численный пример

`N = 2`, `top_k = 5`, промпт: `"The capital of France is"`. Числа иллюстративные.

Распределения после forward pass:

| Модель A | p    | Модель B | p    |
| -------- | ---- | -------- | ---- |
| `Paris`  | 0.55 | `Par`    | 0.50 |
| `Par`    | 0.20 | `Paris`  | 0.25 |
| `P`      | 0.10 | `Pa`     | 0.12 |
| `The`    | 0.10 | `The`    | 0.08 |
| `It`     | 0.05 | `Lyon`   | 0.05 |

**Символ 0.** `P`: A даёт 0.55+0.20+0.10 = 0.85, B даёт 0.50+0.25+0.12 = 0.87 → `(0.85+0.87)/2 = 0.860`.
`T`: `(0.10+0.08)/2 = 0.090`. `I`: 0.025. `L`: 0.025.
Победитель — `P`. Префикс: `"P"`. Отсеиваются `The`, `It`, `Lyon`.

**Символ 1.** Токен `P` у модели A короче позиции 1 → достраивается: `P`+`aris` (0.10 · 0.70 = 0.07), `P`+`arisian` (0.10 · 0.20 = 0.02).
`a`: A даёт 0.55+0.20+0.09 = 0.84, B даёт 0.50+0.25+0.12 = 0.87 → 0.855. Победитель — `a`, префикс `"Pa"`.

**Символ 2.** Аналогично побеждает `r`, префикс `"Par"`. Токен `Pa` модели B достраивается.

**Символы 3–4.** Побеждают `i`, `s`. После фильтрации по префиксу `"Paris"` у обеих моделей остаётся ровно один кандидат → условие остановки выполнено.

**Результат шага:** `commonprefix(["Paris", "Paris"]) = "Paris"` — 5 символов за один шаг ансамбля, при том что модель B такого токена в top-1 не имела.

## 4. Установка

Требуется Python 3.12+. Проект использует [uv](https://docs.astral.sh/uv/).

```bash
git clone -b cli https://github.com/Misha-the-Creator/PrefixSelection.git
cd PrefixSelection
uv sync
```

Через pip:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .
```

Основные зависимости: `torch>=2.12`, `transformers>=5.13`, `accelerate`, `click`, `evalplus`, `polars`, `matplotlib`.

Модели загружаются в `float16` с `device_map="auto"`. Ориентир по памяти: два ансамблируемых чекпоинта на 7B требуют ≈ 28 ГБ VRAM (2 × 7 · 10⁹ × 2 байта).

## 5. Использование

```bash
uv run python src/prefixselection/main.py
```

Запуск без подкоманды открывает интерактивное меню (RU / EN):

```
  1. Добавить модель к ансамблю
  2. Выполнить генерацию в ответ на ввод
  0. Выход
```

Подкоманды доступны и напрямую:

```bash
# добавить модель (имя проверяется через huggingface_hub.repo_exists)
python src/prefixselection/main.py --lang RU load-model --model Qwen/Qwen2.5-1.5B-Instruct

# генерация
python src/prefixselection/main.py --lang RU enter-generation-text
```

`load-model` вызывается столько раз, сколько моделей нужно в ансамбле. Ограничения на `N` в коде нет.

## 6. Гиперпараметры

| Параметр         | Где задан             | Значение  | Смысл                                              |
| ---------------- | --------------------- | --------- | -------------------------------------------------- |
| `top_k`          | `Generation.__init__` | 5         | Размер усечённого распределения каждой модели      |
| `max_steps`      | `PrefixDense`         | 300       | Максимум шагов ансамбля                            |
| `max_char_steps` | `match_chars`         | 128       | Максимальная длина префикса за один шаг            |
| `votes_ratio`    | `_check_eos`          | 0.5       | Доля моделей со стоп-токеном в top-1 для остановки |
| `mass_threshold` | `_check_eos`          | 0.5       | Порог средней вероятностной массы стоп-токенов     |
| `torch_dtype`    | `cli.load_model`      | `float16` | Точность весов                                     |

## 8. Вычислительная стоимость

Основная цена метода — достраивание коротких токенов. За один шаг ансамбля:

```
forward passes ≈ N + N · K · L_extend
```

где `L_extend` — число позиций, где потребовалось достраивание. При `N = 2`, `K = 5` и префиксе в 5 символов с достраиванием на 2 позициях это ≈ 2 + 2·5·2 = 22 forward pass на ~5 сгенерированных символов против 1 pass на токен у обычного greedy-декодирования.

Снижение `top_k` уменьшает стоимость линейно, но повышает риск, что консенсусный символ не покрывается усечённым распределением.

## 9. Ограничения

- Агрегация — жадная (`argmax` на каждом символе); sampling, beam search и температура не реализованы.
- Каждая модель хранится в памяти целиком и опрашивается на каждом шаге.
- Позиция символа берётся из сырой строки токена, включая маркеры пробела (`Ġ`, `▁`) — модели с разными соглашениями о пробелах могут расходиться на первом символе.
- Список стоп-токенов задаётся вручную; при новых семействах моделей его нужно расширять.
- В ветке `cli` нет тестов и скриптов воспроизведения экспериментов.
